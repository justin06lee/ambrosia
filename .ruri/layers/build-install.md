# ambrosia — Build and Install

One layer of ambrosia's stack, owning `Makefile, package.json, tsconfig.json, tools/install.sh`. The whole stack, and how the layers connect, is in `.ruri/architecture.md`.
Don't edit this file: ruri writes it. `ruri layer build-install` prints it with every line numbered, what git says changed in this layer lately and what sessions learned working here; once you have read it that way, put right what your work changed — `ruri layer build-install add|set|drop <section> …`. Where it and the code disagree, the code is right.

This layer installs the already-generated themes for the current Linux user into XDG config/data directories. It is a POSIX sh script that copies from dist/ with per-file backup of non-ambrosia files. The key idea: install never loses user data — foreign files become <name>.before-ambrosia, ambrosia-owned files are overwritten silently.

## Where to change what

- **Per-user theme install:** tools/install.sh
- **GTK variant selection (light/dark via gsettings):** tools/install.sh
- **Backup of pre-existing user files:** tools/install.sh

## How it works

- **Install themes:** Resolve dist/ relative to script location → Exit early (success) on non-Linux, pointing at dist/ → Detect GTK mode via gsettings color-scheme (default light) → place() each dist artifact into XDG_CONFIG_HOME / XDG_DATA_HOME, backing up foreign files

## Key files

- tools/install.sh — installs dist/ themes per-user with .before-ambrosia backups and GTK light/dark pick

## Rules and traps

- Run from any cwd: dist path is derived from the script location, not cwd.
- Non-Linux is not an error: exit 0 after pointing at dist/.
- Only files lacking the 'Generated by ambrosia' marker are backed up; never delete a .before-ambrosia backup by overwriting blindly.
- GTK3 gets only the active mode file copied as gtk.css; GTK cannot follow system scheme alone.

## What it talks to

- Generator Core — install only copies dist/ output, never generates it
- Theme Targets — dist gtk-3.0/gtk-*.css, gtk-4.0/gtk.css, kde colors are its install inputs
- Linux desktop (XDG dirs, gsettings) — reads color-scheme, writes into XDG_CONFIG_HOME and XDG_DATA_HOME
