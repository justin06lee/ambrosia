# ambrosia — Build and Install

One layer of ambrosia's stack, owning `Makefile, package.json, tsconfig.json, tools/install.sh`. The whole stack, and how the layers connect, is in `.ruri/architecture.md`.
Don't edit this file: ruri writes it. `ruri layer build-install` prints it with every line numbered, what git says changed in this layer lately and what sessions learned working here; once you have read it that way, put right what your work changed — `ruri layer build-install add|set|drop <section> …`. Where it and the code disagree, the code is right.

This layer builds, tests and installs Ambrosia. Bun and TypeScript handle the build, Make orchestrates the targets, and a POSIX sh script installs the already-generated themes for the current Linux user into XDG config and data directories. Install copies from dist/ and backs up foreign files. The key idea: install never loses user data, since foreign files become <name>.before-ambrosia and ambrosia-owned files are overwritten silently. Make publish also pushes the signed Arch package repo to GitHub Releases.

## Where to change what

- **Per-user theme install:** tools/install.sh
- **GTK variant selection (light/dark via gsettings):** tools/install.sh
- **Backup of pre-existing user files:** tools/install.sh
- **make package / quickshell / iso targets (Arch):** Makefile
- **Publish signed Arch package repo (make publish):** Makefile, tools/publish-repo.sh
- **Running the build gate, review site and screenshots on tenet (make remote-build, review-remote, shot-remote):** Makefile, tools/remote.sh

## How it works

- **Install themes:** Resolve dist/ relative to script location → Exit early (success) on non-Linux, pointing at dist/ → Detect GTK mode via gsettings color-scheme (default light) → place() each dist artifact into XDG_CONFIG_HOME / XDG_DATA_HOME, backing up foreign files
- **Publish package repo:** make publish runs tools/publish-repo.sh → Build the packages under packaging/ → Sign the repo db with the private key, which stays on the Mac → Copy ambrosia.db and ambrosia.files as real files, since release assets cannot be symlinks → Upload to the rolling `repo` release in justin06lee/ambrosia-packages
- **Remote work:** make remote-build / review-remote / shot-remote (Mac) → tools/remote.sh pushes HEAD to tenet's bare repo ~/git/ambrosia.git → ~/work/ambrosia resets to it, uncommitted changes rsynced on top → the command runs capped there → review-remote tunnels localhost:4747 over ssh; shot-remote (headless Firefox, 1440x900) copies out/shots/<SHOT>.png back

## Key files

- tools/install.sh — installs dist/ themes per-user with .before-ambrosia backups and GTK light/dark pick
- Makefile — build, test, dist, package and publish targets, and the remote-* / shot-remote targets that run on tenet
- tools/publish-repo.sh — builds, signs and uploads the pacman repo to the public releases

## Rules and traps

- Run from any cwd: dist path is derived from the script location, not cwd.
- Non-Linux is not an error: exit 0 after pointing at dist/.
- Only files lacking the 'Generated by ambrosia' marker are backed up; never delete a .before-ambrosia backup by overwriting blindly.
- GTK3 gets only the active mode file copied as gtk.css; GTK cannot follow system scheme alone.
- The private signing key never goes into either repo; it lives only on the Mac.
- The source repo stays private; the public ambrosia-packages repo carries built shell QML and session scripts.
- Release assets cannot be symlinks, so the publish step must upload real copies of ambrosia.db and ambrosia.files.
- After Arch updates Qt, bump pkgrel in packaging/quickshell/PKGBUILD and run make publish.
- Heavy work runs on tenet, not the 8 GB Mac: the Mac only edits, runs git and signs. Everything on tenet runs capped (systemd-run --user --scope -p MemoryMax=…, nice 19, ionice -c3, two jobs): it has no swap and hosts mira's gateway.
- tenet's ~/work/ambrosia is disposable: every tools/remote.sh run resets it hard and cleans untracked files (ignored out/, dist/, node_modules survive), so never edit there.
- make shot-remote shows layout and colour, not glass: headless Firefox draws no backdrop blur.

## What it talks to

- Generator Core — install only copies dist/ output, never generates it
- Theme Targets — dist gtk-3.0/gtk-*.css, gtk-4.0/gtk.css, kde colors are its install inputs
- Linux desktop (XDG dirs, gsettings) — reads color-scheme, writes into XDG_CONFIG_HOME and XDG_DATA_HOME
- Packaging — make publish builds and signs the packages defined under packaging/
- GitHub Releases — make publish uploads the repo to the rolling `repo` release in justin06lee/ambrosia-packages
- tenet (Arch build host) — tools/remote.sh over plain ssh as justin06lee@192.168.1.172 (~/.ssh/id_ed25519_justin); git push to its bare repo, no GitHub credentials there
